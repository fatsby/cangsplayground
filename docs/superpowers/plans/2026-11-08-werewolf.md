# Werewolf Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a whole-lobby, app-moderated Werewolf game (Werewolf, Villager, Seer, Guard) with host god view, host role editing, late joining and a public-only projector.

**Architecture:** A new game package `packages/games/werewolf` implements `GameModule<WerewolfConfig, null, WerewolfShared>` using the shared-state path that Shark Tank uses (`prepareShared`, `onSharedAction`, `sharedDeadlines`/`onSharedDeadline`, `sharedViewFor`). All rules are pure functions in `rules.ts`, tested without a server. Two small core/lobby extensions are needed first: a `wholeLobby` flag (one group containing every player) and an `onSharedPlayerJoined` hook (late join).

**Tech Stack:** TypeScript, zod (config), React (views), vitest, pnpm workspace. Mirror `packages/games/shark-tank` (module shape, package.json, tsconfig, css.d.ts) and `packages/games/whos-the-spy` (secret roles, vote, per-viewer filtering).

**Spec:** `docs/superpowers/specs/2026-11-08-werewolf-design.md`

**Visual reference (approved):** `docs/superpowers/specs/2026-11-08-werewolf/screens.html` — open it in a browser. Every web task ports its screens and animations from it. Where the plan and the mockup disagree on look or motion, the mockup wins; on rules, the spec wins.

## Global Constraints

- English only for all UI text and content.
- Minimum 5 players to start. Defaults: night 30 s, discussion 180 s, vote 60 s. Role-reveal 10 s, `DAWN_MS = 8000`, and a new `VERDICT_MS = 9000` stage (approved with the mockup) that plays the vote-result reveal before the next night or the final screen.
- Roles: `werewolf`, `villager`, `seer`, `guard`. Default split: werewolves = `max(1, Math.round(n / 4))`, one seer, one guard, rest villagers.
- Night always runs its full duration (never ends early).
- Day vote resolves only when the timer ends. Elimination needs `Math.ceil(alive / 2)` votes; a tie between players who both reach it, or nobody reaching it, eliminates no one. No self-votes; votes can be changed until the timer ends.
- Win: village when no werewolves remain; wolves when living werewolves >= living non-werewolves. Checked after each dawn and each day vote.
- Stage order: `NIGHT → DAWN → (DISCUSSION | ENDED)` and `VOTE → VERDICT → (NIGHT | ENDED)`. The win check runs when the night or vote is resolved, but the winner stays hidden from every viewer until `ENDED`, so the kill and verdict animations play first.
- Villager night taps are decoys: the UI lets them tap names and sends nothing to the server. The Seer's first pick each night is locked. The Guard is never told whether the protection mattered.
- The projector highlights a player who has reached the vote threshold before the timer ends (counts only, never who voted).
- Sound effects are off by default, behind a toggle.
- Dawn announcement does not distinguish "protected" from "no attack". Eliminated players' roles stay hidden until the game ends.
- Guard may self-protect once per game and may protect the same player on consecutive nights. Seer cannot investigate self; sees only "werewolf" / "not werewolf".
- Host does not play. Late joiners enter at the next dawn with a host-chosen role (default villager).
- Per-viewer filtering is mandatory: no hidden information may reach another viewer or the projector in any payload.
- Show every player with their lobby-customised avatar via `PlayerAvatar` (`packages/ui/src/avatar.tsx`), never initials. Late joiners have the default seeded avatar (the lobby locks avatar edits once a game is selected).
- Repo principles: one top-level type per file, doc comments on public APIs, reuse before writing, no nested types.

## Review Focus

Each line below has a pinning test in the task named in brackets.

1. 4 alive with a 2-2 split, 2 alive with mutual votes, votes from/for dead players — must eliminate no one or the correct player. [Task 1, Task 5]
2. A late joiner arriving during SETUP, REVEAL, NIGHT, DISCUSSION and VOTE, and two joiners at once — must never stall or leak the role. [Task 2, Task 6]
3. The last werewolf, or the Seer/Guard, leaving or disconnecting mid-night — night still lasts its full duration and the win check re-runs. [Task 6]
4. A phase timer expiring with no input from anyone (all phones offline) — game advances, never stalls. [Task 4, Task 5]
5. Reconnecting phones and the projector receiving payloads — no role, night choice, seer result or voter identity beyond what the viewer may see. [Task 7]
